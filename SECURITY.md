# Security Policy

## Audit Status Disclaimer

> [!WARNING]
> **Audit Status:** The smart contracts (`contracts/sla_registry`) and monitoring services in this repository are currently **UNAUDITED**. Use in production environments at your own risk.

---

## Reporting Vulnerabilities

We take security seriously. If you discover a security vulnerability within **SEP-Pulse**, please follow responsible disclosure guidelines.

**DO NOT create a public GitHub issue for security vulnerabilities.**

Instead, please email the lead maintainer directly:

- **Lead Maintainer:** Abdulmalik Ojo
- **Security Email:** [abdulmalikojo2@gmail.com](mailto:abdulmalikojo2@gmail.com)
- **Telegram Contact:** [@tecmalik](https://t.me/tecmalik)

Include the following details in your report:
1. Type of issue (e.g., buffer overflow, unhandled error loop, auth key leakage, contract storage vulnerability).
2. Step-by-step proof-of-concept (PoC) or reproduction steps.
3. Impact assessment.

---

## Response & Disclosure Timeline

- **Acknowledgement:** Within 24-48 hours of report receipt.
- **Assessment & Fix:** We will endeavor to patch verified critical vulnerabilities within 7 days.
- **Public Disclosure:** Coordinated after a fix is deployed to mainnet / release tags.
